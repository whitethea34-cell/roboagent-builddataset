## 二、执行步骤

### Phase 1：构建 Q&A 测试集生成器 → `qa_testset.json`

**输入**：`task_plan_testset.json`（50 道开放生成题）
**输出**：`qa_testset.json`（~500 道诊断选择题/判断题）
**时长**：主要编码工作

**生成策略**：模板引擎 + gold 数据填充

对每道 DOG 题，按以下维度模板派生子题：

#### D1 模板 — 任务拆解（2-4题/源题）
| 模板ID | 题型 | 生成逻辑 |
|--------|------|----------|
| D1_order | 单选 | 打乱 `stages_expected` 顺序，正确答案为原始顺序 |
| D1_count | 单选 | 问阶段数量，正确=gold阶段数 |
| D1_match | 单选 | 给动作列表，选正确的阶段名 |

#### D2 模板 — 时序理解（2-5题/源题）
| 模板ID | 题型 | 生成逻辑 |
|--------|------|----------|
| D2_precond | 单选 | 选某关键动作的必要前置条件（从 deps 提取） |
| D2_violation | 单选 | 构造含顺序错误的序列，问哪步有问题 |
| D2_next | 单选 | 给部分已完成步骤，问下一步该做什么 |

#### D3 模板 — 物体/动作依赖（0-3题/源题，仅涉及物品操作时生成）
| 模板ID | 题型 | 生成逻辑 |
|--------|------|----------|
| D3_perception | 单选 | CARRY前必须做什么？FIND/NAVIGATE/OBSERVE |
| D3_target | 单选 | CARRY的目标应该是？从gold target字段取 |
| D3_chain | 单选 | 操作链完整性判断 |

#### D4 模板 — 场景/条件判断（1-3题/源题）
| 模板ID | 题型 | 生成逻辑 |
|--------|------|----------|
| D4_location | 单选 | 物品/人在哪？从scene和target推导 |
| D4_target_dest | 单选 | 操作对象应该送到哪？ |
| D4_branch | 单选 | 仅Type E：条件分支选择 |

#### D5 模板 — 安全与社交（1-4题/源题）
| 模板ID | 题型 | 生成逻辑 |
|--------|------|----------|
| D5_hri | 判断 | 该任务是否需要HRI？gold hri_expected |
| D5_social_act | 单选 | HRI=是时，应包含什么社交动作？ |
| D5_safety | 单选 | 安全红线判断（全部题型共用一批通用安全题） |

**干扰项生成规则**：
- `reversed_order`: 反转依赖顺序
- `wrong_object`: 替换为场景中不相关的物体
- `wrong_location`: 替换为错误位置
- `missing_step`: 跳过关键步骤
- `extra_step`: 插入不相关步骤
- `wrong_social`: 社交动作错误

### Phase 2：构建 Q&A 评测引擎 → `qa_evaluator.py`

与开放生成评测不同，Q&A 评测极其简洁：

```python
# 核心评分逻辑：答案比对
def score_qa(pred_answer: str, gold_answer: str) -> float:
    """选择题/判断题评分：pred == gold → 1.0 else 0.0"""
    return 1.0 if pred_answer.strip().upper() == gold_answer.strip().upper() else 0.0
```

**按维度聚合**：
- 每道题有 `dimension` 字段
- 汇总时按 D1~D5 分别计算准确率
- 输出 `{D1: 0.85, D2: 0.72, D3: 0.68, D4: 0.75, D5: 0.91}`

**解析 LLM 输出**：从模型回复中提取选项字母（A/B/C/D）或判断（是/否）

### Phase 3：构建批量测试脚本 → `qa_batch_runner.py`

参照 `batch_test_scheduler.py` 的模式：
- 加载 `qa_testset.json`
- 逐题发送给 llama-server HTTP API
- 解析回复提取答案
- 评分并记录
- 按维度聚合统计
- 输出 `qa_results_{tag}_{timestamp}.json` + summary TXT

### Phase 4：构建多轮汇总 → `qa_generate_summary.py`

参照 `generate_summary.py` 的模式：
- 扫描目录下所有 `qa_results_*.json`
- 生成 Markdown 表格（版本 × 五维度准确率）
- 附各版本提示词全文

### Phase 5：冒烟验证

在 WSL Docker 8083 端口运行：
```bash
# 1. 选5题快速验证
python qa_batch_runner.py --port 8083 --limit 5 --tag smoke-test

# 2. 验证五维度独立打分
python qa_evaluator.py  # 单元测试

# 3. 验证多轮汇总
python qa_generate_summary.py
```
