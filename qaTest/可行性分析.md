# Q&A 评测方案可行性分析

> 日期：2026-05-14
> 参考：ERIQ 评测集（智元具身研究中心）纯选择题/判断题设计思路

---

## 一、现状问题诊断

### 当前评测的四个维度被"混在一起"

```
用户指令: "把门口的快递取来给我"
    ↓
模型一次生成完整输出:
    HRI：是
    阶段：取件→运送→递送
    1. NAVIGATE|玄关
    2. WALK|玄关
    3. FIND|快递
    ...
    ↓
评分引擎一次性打一个总分（含4个子维度）
```

**问题**：当模型得分低时，无法判断是哪个推理环节出了问题：

- 是阶段划分错了？（任务拆解）
- 是 FIND 放在了 CARRY 后面？（时序理解）
- 是操作了错误的目标物体？（物体依赖）
- 是没有判断快递在玄关而非客厅？（场景理解）
- 是没识别出需要对主人做社交动作？（社交判断）

当前评分引擎的 breakdown 能给出各维度分数，但各维度分数仍然是**从同一份输出中提取的**，维度之间存在耦合。例如，"目标达成"中的目标匹配依赖于动作是否被正确解析，而解析又依赖于输出格式——格式问题会污染所有维度。

### ERIQ 的解决思路

每个推理子能力用**独立的、封闭答案的选择题/判断题**单独测试：

- 测"错误识别" → 给一段含错误的动作序列，问"哪里错了？A/B/C/D"
- 测"任务规划" → 给场景描述，问"下一步应该做什么？A/B/C/D"
- 测"人机协作" → 给含手势的图片，问"人想要什么？A/B/C/D"

每道题只测一个维度，答案完全确定，评分 = `pred == gold ? 1 : 0`。

## 二、方案设计

### 从 50 道现有题目中抽取诊断性子题

不抛弃现有的 50 题开放生成评测（作为集成测试保留），而是从每道题中**派生**出若干独立的诊断性子题。

**示例：DOG-B01 "把门口的快递取来给我"**

| 原题中的推理要素 | 可派生的Q&A子题 |
|-----------------|----------------|
| HRI=是 | D5-判断: "该任务是否需要与人交互？ A.是 B.否" |
| 阶段"取件→运送→递送" | D1-排序: "正确阶段顺序？ A.取件→递送→运送 B.运送→取件→递送 C.取件→运送→递送" |
| FIND→CARRY→DROP 依赖链 | D3-单选: "CARRY(快递)的前置条件？ A.已完成NAVIGATE(玄关) B.已FIND(快递) C.已SPEAK" |
| CARRY 后去"主人位置" | D4-单选: "取到快递后，下一步应前往？ A.玄关 B.主人位置 C.充电桩" |
| 递送阶段的社交动作 SPEAK/BOW | D5-单选: "递送物品时应伴随什么动作？ A.仅DROP B.SPEAK+BOW+DROP C.仅WAVE" |
| OBSERVE → FIND 的感知链 | D3-单选: "FIND(快递)前必须先？ A.NAVIGATE到目标区域+OBSERVE B.直接FIND C.SPEAK" |

一道开放生成题 → 可派生 3~6 道诊断性 Q&A 子题。50 道题预计可派生 **200~300 道诊断子题**。

## 三、五个诊断维度详细定义

### D1 — 任务拆解（阶段划分能力）

**测什么**：模型是否理解任务的宏观结构——应该分几个阶段，阶段之间什么关系。

**题型**：
- 阶段排序：给打乱的阶段名，选正确顺序
- 阶段选择：给场景描述，选最合理的阶段划分方案
- 阶段匹配：给每个阶段的动作列表，匹配阶段名

**与当前评分的关系**：对应 `score_stage_quality`，但独立测试，不受动作序列质量影响。

### D2 — 时序理解（依赖拓扑）

**测什么**：模型是否理解动作间的前置/后置关系——什么必须先做，什么必须后做。

**题型**：
- 前置条件选择："执行动作X之前，必须先完成什么？"
- 违规检测："以下序列中哪一步的顺序有误？"
- 下一步预测："当前已完成[A,B,C]，下一步应该执行？"

**与当前评分的关系**：对应 `score_execution_quality` 中的依赖满足度，但将依赖关系单独拎出来测试。

### D3 — 物体/动作依赖（操作链）

**测什么**：模型是否理解操作物体的因果链——感知→定位→抓取→搬运→交付。

**题型**：
- 动作前提："CARRY一个物体的前提是什么？"
- 目标选择："FIND指令的目标应该是什么？"
- 操作链完整性："取物→运送→递送链中，哪步缺失会导致任务失败？"

**与当前评分的关系**：对应 `score_goal_achievement` 中的目标精确度和动作类覆盖。

### D4 — 场景/条件判断（环境推理）

**测什么**：模型是否理解环境条件对任务执行的影响——人/物在哪、路通不通、条件触发分支选择。

**题型**：
- 位置推理："快递最可能在哪个位置？A.玄关 B.卧室 C.厨房"
- 条件分支："如果路被堵了，应该？A.放弃 B.绕行 C.等待 D.硬闯"
- 目标选择："送给张工的文件应该送到？A.301室 B.302室 C.前台"

**与当前评分的关系**：对应 Type E 的分支路径评估，将条件判断独立测试。

### D5 — 安全与社交判断（交互边界）

**测什么**：模型是否理解与人交互的安全边界和社交规范。

**题型**：
- HRI判断：判断题，直接问"该任务是否需要与人交互"
- 安全红线："CARRY|人 是否可以？"
- 社交动作选择："送东西给人时，应该附加什么社交动作？"
- 社交场景识别："收到'谢谢'后，机器人应该？"

**与当前评分的关系**：对应 `score_safety_social`，将安全判断从生成质量中解耦。

## 四、题目格式

采用统一 JSON Schema（详见 `schema/question_schema.json`）：

```json
{
  "qa_id": "QA-D2-B01-001",
  "source_test_id": "DOG-B01",
  "dimension": "D2",
  "sub_dimension": "dependency_topology",
  "difficulty": "easy",
  "type": "single_choice",
  "question": "在'取快递送给主人'的任务中，CARRY(快递)必须在以下哪步之后执行？",
  "options": [
    {"key": "A", "text": "FIND(快递) 之后"},
    {"key": "B", "text": "SPEAK(您的快递) 之后"},
    {"key": "C", "text": "DROP 之后"},
    {"key": "D", "text": "BOW 之后"}
  ],
  "answer": "A",
  "explanation": "必须先找到快递（FIND）才能搬运（CARRY），这是感知→操作的因果链。"
}
```

## 五、可行性评估

### 优势

| 方面 | 评估 |
|------|------|
| **诊断精度** | 高。每道题只测一个推理子能力，错误可以精确定位到维度×子维度 |
| **评分客观性** | 极高。评分 = 字符串比对 `pred_key == answer_key`，零歧义 |
| **可复现性** | 极高。任何人在任何时间跑同一模型得相同分数 |
| **扩展性** | 高。新增场景只需按维度模板派生新题，无需重写评分逻辑 |
| **与现有评测互补** | 现有 50 题作为"集成测试"保留，Q&A 作为"单元测试"补充 |
| **LLM 兼容性** | 高。选择题是最基础的 LLM 评测范式，所有模型都支持 |

### 风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| 选择题有猜测概率（4选1=25%随机正确率） | 增大每维度的题量（≥30题），统计显著性可抵消猜测 |
| 派生题目可能过于简单（直接从 gold 反推） | 增加错误选项的迷惑性（从常见模型错误中采样）、增加否定句式 |
| 题目编写工作量大 | 用 LLM 辅助从现有 50 题 gold 中批量派生，人工审核 |
| 对开放生成能力的评测缺失 | 明确 Q&A 定位为**诊断补充**而非替代，保留原 50 题开放评测 |
| 纯文本题目缺乏视觉输入 | 初期用文本描述替代图像（符合当前调度器纯文本接口），未来可扩展 VL 题型 |

### 建议的实施路径

```
Phase 1: 验证（2-3题试点）
  从 DOG-B01 派生全套 5 维度诊断题 → 用现有模型跑 → 对比开放评测得分

Phase 2: 扩展（全50题覆盖）
  50题 × 平均4子题 = ~200题 → 建立 coverage_matrix.md

Phase 3: 标准化
  确定每维度最低题量（建议≥30题） → 平衡难度分布 → 标定基线

Phase 4: 集成
  qaTest 结果与 task_plan_evaluator 结果做相关性分析
```

## 六、结论

**方案可行。** 核心逻辑成立：

1. 现有 50 道开放生成题中蕴含的推理要素可以被拆解为独立的诊断性子题
2. 选择题/判断题格式保证了评分的确定性、可复现性和诊断精度
3. Q&A 评测作为**诊断层**补充现有**集成评测**，两者互补而非替代
4. ERIQ 的成功验证了"封闭题型评测 → 模型改进 → 开放任务提升"的路径有效性

**下一步建议**：从 DOG-B01 开始试点，手动编写 5 个维度的诊断样题，用现有模型验证诊断效果。
