# D3 物体/动作依赖 — 难度分析与知行差距诊断

> 时间: 2026-05-14
> 模型: 0.8B (llama-server port 8083, T=0.3)
> 测试集: v2 (514题, D3新生成器 52题)

## 一、D3 题目难度提升

旧版 D3 测试题（47题）仅覆盖 3 个子维度：
- `perception_chain`（FIND→CARRY→DROP 通用链）
- `target_matching`（CARRY 目标匹配）
- `chain_completeness`（操作链是否完整）

所有题目均为"常识级"难度，模型凭通用知识即可答对。**三轮全量测试 D3 均为 1.0000。**

新版 D3 重写后覆盖 5 个子维度（52题）：
- `class_coverage_gap`（动作大类覆盖诊断，17题）
- `object_action_alignment`（动作-目标配对错误检测，15题）
- `chain_order_validation`（含具体物品名的操作链顺序校验，15题）
- `multi_object_tracking`（多物品任务操作链追踪，3题）
- `target_confusion`（多物品场景目标混淆，2题）

## 三、核心发现：知行差距 (Knowing-Doing Gap)

```
Q&A 选择题 D3 准确率：  ████████████████████████████░  96%+
开放式生成 object_handle 覆盖率： █████████████████████░░░░░  83%
                                  ↑
                            ~13-17% 的差距
```

**模型"知道"但不一定"做到"。**

在 Q&A 封闭式选择题中，模型只需从 4 个选项中识别正确答案——这测试的是**知识存储**（模型内部是否有正确的物体-动作关系规则）。96%+ 的结果表明：**规则是存在的。**

在开放式任务规划生成中，模型需要自主输出完整动作序列——这测试的是**知识检索与应用一致性**。实际 object_handle 类动作缺失率 ~17%，说明：**规则在生成时未被稳定调用。**

### 根因分析

开放式生成中 object_handle 缺失的可能原因：

1. **注意力竞争**：生成时导航/移动类动作占主导，物体操作被"挤出"输出序列
2. **长序列退化**：随着生成 token 数增加，模型对早期约束（如"必须 FIND 再 CARRY"）的遵循度下降
3. **模板偏好**：小模型倾向于输出训练数据中高频出现的动作模式（NAVIGATE/WALK 远多于 CARRY/DROP）
4. **上下文遗忘**：指令中的物品信息在长上下文生成过程中被稀释

### 诊断价值

这正是 Q&A 评测作为**诊断层**的核心价值：
- Q&A 测"知"：模型是否具备正确的领域知识
- 开放生成测"行"：模型是否能在实际规划中稳定调用知识
- **两者差距 = 生成一致性瓶颈的大小**

如果 Q&A 也不及格 → 知识缺失，需要补充训练数据
如果 Q&A 及格但开放生成不及格 → 生成一致性差，需要 prompt 约束、解码策略优化、或更强的基座模型

**当前 D3 情况属于后者。**

## 四、量化精度损失：知行差距的关键放大器

### 确认的量化配置

通过 `/v1/models` 接口确认，8083 端口运行的模型为：

```
模型: Qwen3.5-0.8B-Q4_K_M.gguf
参数量: 752M
模型文件: 521MB (FP16 约 1.5GB, 压缩比 ~3x)
量化方案: Q4_K_M (4-bit, K-quant medium)
上下文: 4096 tokens
```

Q4_K_M 是 llama.cpp 的 4-bit K-quant 方案，每个权重平均 4.5 bits。

### 量化如何放大知行差距

```
                    Q&A 选择题 (短输出)          开放式生成 (长输出)
                    ─────────────────           ─────────────────
输出 token 数:      1~5 tokens                  100~300+ tokens
量化噪声:           单次前向, 噪声不累积         逐 token 累积, 误差叠加
注意力精度:         KV cache < 1K tokens        KV cache 增长至 1~2K tokens
低频 token 召回:     仅需排序, 影响小             需精确采样, 受量化影响大
```

**三个具体机制：**

#### 1. 量化 KV Cache 导致注意力漂移

llama.cpp 默认对 KV Cache 进行 Q8_0 量化（8-bit）。在长序列生成中，量化后的 key-value 对累积误差，导致注意力分布偏离原始精度下的分布。**时序约束**（先 FIND 后 CARRY）和**物体引用**（具体物品名）依赖于注意力头对上下文中特定位置的精确检索——量化 KV Cache 使这种检索逐渐"模糊"。

这直接解释了 **D2（时序理解）为何是最弱维度**（48-56%）——时序判断需要跨长上下文的精确注意力，受 KV Cache 量化影响最大。

#### 2. 低频 Token 的概率质量被量化噪声淹没

Q4_K_M 量化下，每个权重 ±0.5 LSB（最低有效位）的量化误差。对于高频动作（NAVIGATE、WALK）——训练数据中大量出现——即使有量化误差，logits 仍然足够高以被采样。但对于低频动作（CARRY、DROP、PUSH）——训练数据中相对稀少——量化误差足以将其 logits 压低至采样阈值以下。

Q&A 选择题不需要模型从整个词表中采样低频 token——只需在 4 个选项中比较概率——所以量化影响极小。

#### 3. 逐 Token 误差累积

在开放式生成中，第 t+1 个 token 的 hidden state 依赖于第 t 个 token 的量化近似输出。这个误差链在 100+ token 的序列中累积，导致模型逐渐偏离精确的规划轨迹，退化为"safe defaults"（即高频动作模式）。

### 量化影响 vs 模型规模能力的矩阵

```
                 Q&A D3 准确率    开放生成 object_handle    差距
                 ────────────     ─────────────────────    ────
0.8B Q4_K_M     96%+             83%                       ~13%
0.8B FP16       ？(待验证)         ？(待验证)                 ？
4B Q4_K_M       ？(待验证)         ？(待验证)                 ？
4B FP16         ？(待验证)         ？(待验证)                 ？
```

**关键待验证假设**：在 FP16 精度下运行同一 0.8B 模型，知行差距应显著缩小。如果 FP16 下 D3 Q&A 仍 96%+ 但开放生成 object_handle 也提升至 90%+，则量化是主因。如果 FP16 下开放生成仍 ~83%，则模型容量（0.8B 参数）是主因。

### 实践含义

1. **Q&A 评测对量化相对鲁棒**——适合作为 CI 中的快速回归测试，即使在量化模型上也能稳定反映知识边界
2. **开放生成评测需要标注量化配置**——不同量化级别下同一模型的开放生成表现可能差异显著
3. **知行差距的大小本身就是量化敏感度的度量**——差距越大，说明该维度受量化影响越大
4. **D2 (48-56%) 和 D3 知行差距 (~13%) 的共同根源**：都是量化 KV Cache 下的长程注意力退化，只是表现形式不同（D2 是排序错误，D3 是低频动作遗漏）

## 五、后续建议

1. **进一步加难 D3**：加入对抗性干扰项（如正确链中插入一个错误动作的子序列）、组合型错误（同时错对象和错顺序）
2. **D2 是当前最弱维度**（48-56%），且三类提示词均无显著改善——时序理解可能是 0.8B 模型的能力上限
3. **对比 4B/7B 模型**：在更大模型上测试同一套 D3 题，验证知行差距是否随模型规模缩小
4. **D1/D4 也有提升空间**（62-73%），可参照 D3 方法论进行难度审计
